## The collections you need

| Structure | Java class | Ordered? | Key ops | Use in DSA |
| --- | --- | --- | --- | --- |
| Dynamic array | `ArrayList` | insertion | O(1) get/add-end | default list |
| Hash map | `HashMap` | no | O(1) put/get | frequency, lookup |
| Sorted map | `TreeMap` | sorted keys | O(log n) | floor/ceiling, ranges |
| Hash set | `HashSet` | no | O(1) | membership, dedupe |
| Sorted set | `TreeSet` | sorted | O(log n) | ordered unique, ranges |
| Heap | `PriorityQueue` | by priority | O(log n) push/pop | top-K, Dijkstra |
| Stack/queue/deque | `ArrayDeque` | insertion | O(1) both ends | DFS, BFS, monotonic |

<Warning>
Prefer `ArrayDeque` over the legacy `Stack` and `LinkedList` for stack/queue behavior.
`Stack` is synchronized (slow) and extends `Vector`; `ArrayDeque` is faster and cleaner.
Also avoid `Vector`/`Hashtable` entirely.
</Warning>

## Lists: ArrayList & LinkedList

```java
List<Integer> list = new ArrayList<>();
list.add(10);            // append O(1) amortized
list.add(0, 5);          // insert at index O(n)
int x = list.get(1);     // random access O(1)
list.set(1, 99);         // O(1)
list.remove(0);          // remove by index O(n)
Collections.sort(list);  // O(n log n)
int n = list.size();

int[] arr = {5, 2, 9};
list = new ArrayList<>(Arrays.asList(1, 2, 3));  // from values
```

Use `ArrayList` by default. `LinkedList` only helps for O(1) insert/remove at the ends
(and it implements `Deque`) — see [ArrayList vs LinkedList](/docs/collections/list-internals/).

## Maps: HashMap, TreeMap

```java
Map<Character, Integer> freq = new HashMap<>();
for (char c : "banana".toCharArray()) {
    freq.merge(c, 1, Integer::sum);          // idiomatic frequency count
    // or: freq.put(c, freq.getOrDefault(c, 0) + 1);
}
freq.getOrDefault('z', 0);                   // safe default
freq.computeIfAbsent('a', k -> 0);
for (Map.Entry<Character, Integer> e : freq.entrySet()) { /* iterate */ }

// TreeMap: sorted keys, navigation
TreeMap<Integer, String> tm = new TreeMap<>();
tm.floorKey(5);    // greatest key <= 5
tm.ceilingKey(5);  // smallest key >= 5
tm.firstKey(); tm.lastKey();
```

<Tip>
`merge(key, 1, Integer::sum)` and `getOrDefault` are the cleanest ways to build
frequency maps — a pattern you'll use constantly in hashing/string problems.
</Tip>

## Sets: HashSet, TreeSet

```java
Set<Integer> seen = new HashSet<>();
if (!seen.add(x)) { /* x was already present -> duplicate */ }
seen.contains(x);   // O(1)

TreeSet<Integer> ts = new TreeSet<>();   // sorted, O(log n)
ts.floor(5); ts.ceiling(5); ts.first(); ts.last();
```

`add` returns `false` if the element already existed — a neat duplicate check.

## PriorityQueue (heap)

```java
// Min-heap (default): smallest on top
PriorityQueue<Integer> minHeap = new PriorityQueue<>();

// Max-heap: largest on top
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

minHeap.offer(5); minHeap.offer(1);
int top = minHeap.peek();    // 1, does not remove
int out = minHeap.poll();    // 1, removes

// Heap of custom objects by a field
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);  // by index 1
```

<Warning>
Don't use `a[1] - b[1]` subtraction comparators when values can be large/negative — it
can overflow. Prefer `Integer.compare(a[1], b[1])`.
</Warning>

## ArrayDeque: stack & queue

```java
// Stack (LIFO) — use push/pop/peek on the front
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2);
stack.pop();    // 2
stack.peek();   // 1

// Queue (FIFO) — offer at tail, poll from head
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1); queue.offer(2);
queue.poll();   // 1

// Deque (both ends) — used by monotonic-queue problems
queue.offerFirst(0); queue.offerLast(3);
queue.pollFirst(); queue.pollLast();
```

## Arrays & StringBuilder

```java
int[] a = new int[5];                 // zero-filled
Arrays.fill(a, -1);
int[] b = {3, 1, 2};
Arrays.sort(b);                        // O(n log n)
int[] copy = Arrays.copyOfRange(b, 0, 2);
int idx = Arrays.binarySearch(b, 2);   // requires sorted
int[][] grid = new int[3][4];

// 2D sort by first column, then second
int[][] pairs = {{1,3},{2,1},{1,2}};
Arrays.sort(pairs, (x, y) -> x[0] != y[0] ? x[0] - y[0] : x[1] - y[1]);

// Build strings efficiently (never += in a loop)
StringBuilder sb = new StringBuilder();
sb.append("ab").append(5);
sb.reverse();
String s = sb.toString();
char[] chars = s.toCharArray();
```

## equals, hashCode & ==

<Important>
`==` compares **references** for objects (identity), or values for primitives.
`.equals()` compares **logical equality**. `HashMap`/`HashSet` use `hashCode()` to pick
a bucket and `equals()` to match inside it — so any custom key class **must override
both** consistently, or lookups silently fail. Full detail:
[equals & hashCode](/docs/oop/equals-hashcode/).
</Important>

```java
Integer a = 1000, b = 1000;
System.out.println(a == b);        // false! (outside -128..127 cache)
System.out.println(a.equals(b));   // true  — always use equals for wrappers

// A record auto-generates value-based equals/hashCode — perfect for map keys
record Cell(int r, int c) {}
Map<Cell, Integer> visited = new HashMap<>();
```

## Comparable, Comparator & custom sorting

- **`Comparable`** — a type's single *natural* order (`compareTo`).
- **`Comparator`** — external, reusable orderings (great with lambdas).

```java
// Natural order
class Item implements Comparable<Item> {
    int price;
    public int compareTo(Item o) { return Integer.compare(this.price, o.price); }
}

// Comparators (lambdas) — ascending, descending, multi-key
list.sort(Comparator.comparingInt(Item::getPrice));                 // asc
list.sort(Comparator.comparingInt(Item::getPrice).reversed());      // desc
list.sort(Comparator.comparing(Item::getName)
                    .thenComparingInt(Item::getPrice));             // tie-break

// Sort an int[][] by column 0 desc
Arrays.sort(mat, (x, y) -> Integer.compare(y[0], x[0]));
```

See [Comparable & Comparator](/docs/collections/comparable-comparator/) for depth.

## Complexity cheat sheet

| Operation | ArrayList | HashMap/HashSet | TreeMap/TreeSet | PriorityQueue | ArrayDeque |
| --- | --- | --- | --- | --- | --- |
| add | O(1)* | O(1) | O(log n) | O(log n) | O(1) |
| remove | O(n) | O(1) | O(log n) | O(log n) peek/poll | O(1) ends |
| contains/get | O(1) index / O(n) value | O(1) | O(log n) | O(n) | O(n) |
| min/max | O(n) | O(n) | O(1) first/last | O(1) peek | O(1) ends |

\*amortized. Averages assume good hash distribution.

## Things You Should Know

### 🔴 Must Know
- Which collection to use and its complexity.
- `merge`/`getOrDefault` for frequency maps; `set.add` returns false on duplicate.
- `equals`/`hashCode` contract for custom map keys; records for coordinate keys.
- Min-heap vs max-heap construction; `ArrayDeque` for stack/queue.

### 🟡 Good to Know
- `Comparator.comparing(...).thenComparing(...)`; avoid subtraction comparators.
- `TreeMap` floor/ceiling for ordered queries.
- `StringBuilder` for string building.

### 🟢 Nice to Know
- `Arrays.sort` uses dual-pivot quicksort for primitives, Timsort for objects.
- Fail-fast iterators and `ConcurrentModificationException`.
