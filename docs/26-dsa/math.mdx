## GCD & LCM

The Euclidean algorithm computes the greatest common divisor in O(log min(a,b)).

```java
int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }
long lcm(int a, int b) { return (long) a / gcd(a, b) * b; }   // divide first: avoid overflow
```

<Tip>
Compute LCM as `a / gcd(a,b) * b`, not `a * b / gcd`, to avoid overflowing before the
division. GCD underlies fraction reduction, cycle problems, and `gcd`-of-array questions.
</Tip>

## Primes & the Sieve

### Sieve of Eratosthenes — count primes below n in O(n log log n)

```java
// Count Primes — LeetCode 204
int countPrimes(int n) {
    if (n < 3) return 0;
    boolean[] composite = new boolean[n];
    int count = 0;
    for (int i = 2; i < n; i++) {
        if (composite[i]) continue;
        count++;
        for (long j = (long) i * i; j < n; j += i)   // mark multiples from i*i
            composite[(int) j] = true;
    }
    return count;
}
```

<Important>
Start marking multiples at `i*i` (smaller multiples are already marked by smaller
primes) and use `long` for `i*i` to avoid overflow. The sieve is the standard way to
get all primes up to n; trial division per number is far slower.
</Important>

## Modular arithmetic

Results are often required "modulo 1e9+7" to keep numbers in `long` range.

```java
static final int MOD = 1_000_000_007;
long add(long a, long b) { return (a + b) % MOD; }
long mul(long a, long b) { return (a % MOD) * (b % MOD) % MOD; }
```

Identities: `(a + b) % m = ((a%m) + (b%m)) % m`, and similarly for multiplication.
Division needs the **modular inverse** (via Fermat's little theorem: `a^(m-2) % m` when
`m` is prime).

## Fast exponentiation

Compute `base^exp` in O(log exp) by squaring — with or without a modulus.

```java
// Binary exponentiation, mod m
long power(long base, long exp, long mod) {
    long result = 1;
    base %= mod;
    while (exp > 0) {
        if ((exp & 1) == 1) result = result * base % mod;  // include this bit
        base = base * base % mod;                          // square
        exp >>= 1;
    }
    return result;
}
```

<Interview>
"Compute x^n" (LeetCode 50, *Pow(x, n)*) expects **fast exponentiation** — O(log n), not
the naive O(n) loop. The same halving idea, with a modulus, powers modular inverse and
large combinatorics.
</Interview>

## Combinatorics

- **Permutations:** `nPr = n! / (n-r)!`
- **Combinations:** `nCr = n! / (r!(n-r)!)`
- Precompute factorials (and inverse factorials mod p) for repeated `nCr` queries.
- Pascal's triangle gives `nCr` via `C(n,r) = C(n-1,r-1) + C(n-1,r)`.

```java
// Pascal's Triangle row-by-row DP
List<List<Integer>> generate(int numRows) {
    List<List<Integer>> tri = new ArrayList<>();
    for (int i = 0; i < numRows; i++) {
        List<Integer> row = new ArrayList<>();
        for (int j = 0; j <= i; j++)
            row.add(j == 0 || j == i ? 1 : tri.get(i-1).get(j-1) + tri.get(i-1).get(j));
        tri.add(row);
    }
    return tri;
}
```
