# Modern Java (8 → 27)

From Java 8 onward the language became far more expressive, and it keeps evolving
on a strict six-month cadence. Modern Spring code is lambda- and stream-heavy,
records are the default DTO, pattern matching replaces instanceof ladders, and
virtual threads have reshaped how backends handle concurrency.

<Note title="Which version should I target?">
  **Java 25** is the current Long-Term Support (LTS) release (September 2025)
  and the right default for production. **Java 27** (September 2026) is the
  latest feature release but is non-LTS — great for trying new APIs, supported
  only until the next feature release. The next LTS is **Java 29** (September
  2027). This site is current through **JDK 27**.
</Note>

## Lambda expressions

A lambda is a concise anonymous function — an implementation of a functional
interface (one abstract method).

```java
Runnable r = () -> System.out.println("run");
Comparator<String> byLen = (a, b) -> Integer.compare(a.length(), b.length());
list.forEach(item -> process(item));
```

## Functional interfaces

An interface with exactly one abstract method. The `java.util.function` package
ships the essentials:

| Interface           | Signature      | Use                    |
| ------------------- | -------------- | ---------------------- |
| `Predicate<T>`      | `T -> boolean` | filtering, conditions  |
| `Function<T,R>`     | `T -> R`       | transformation/mapping |
| `Consumer<T>`       | `T -> void`    | side effects           |
| `Supplier<T>`       | `() -> T`      | lazy creation          |
| `BiFunction<T,U,R>` | `(T,U) -> R`   | two-arg transform      |
| `UnaryOperator<T>`  | `T -> T`       | same-type transform    |

```java
Predicate<User> isActive = User::isActive;
Function<User, String> toEmail = User::getEmail;
Supplier<Instant> now = Instant::now;
Consumer<String> logIt = log::info;
```

## Method references

Shorthand for lambdas that just call an existing method.

```java
users.stream().map(User::getEmail)      // instance method of the element
users.forEach(System.out::println)      // instance method of an object
list.stream().filter(Objects::nonNull)  // static method
Supplier<List<String>> s = ArrayList::new;  // constructor reference
```

## Optional

`Optional<T>` models "a value that might be absent", replacing null-returning
methods with an explicit, chainable type.

```java
public Optional<User> findByEmail(String email) { ... }

String name = findByEmail(email)
    .map(User::getName)
    .orElse("guest");

User user = findByEmail(email)
    .orElseThrow(() -> new UserNotFoundException(email));
```

<Warning>
  Use `Optional` for **return types**, not fields or method parameters. Don't
  call `.get()` without checking — use `map`/`orElse`/`orElseThrow`. And never
  wrap a collection in `Optional`; return an empty collection instead.
</Warning>

## Records

Immutable data carriers with generated constructor, accessors, `equals`,
`hashCode`, and `toString`. Final since Java 16 and the default for DTOs and
value objects.

```java
public record OrderDto(Long id, String status, BigDecimal total) { }

// Compact canonical constructor for validation
public record Email(String value) {
    public Email {
        if (!value.contains("@")) throw new IllegalArgumentException("bad email");
    }
}
```

## Sealed classes

Restrict which types may extend/implement a type — perfect for modeling a closed
set of variants that pattern matching can exhaustively check. Final since Java 17.

```java
public sealed interface PaymentResult
    permits Approved, Declined, Pending { }

public record Approved(String txId) implements PaymentResult { }
public record Declined(String reason) implements PaymentResult { }
public record Pending(String ref) implements PaymentResult { }
```

## Pattern matching & switch expressions

Pattern matching for `switch` became final in Java 21.

```java
String describe(PaymentResult result) {
    return switch (result) {                 // exhaustive over the sealed type
        case Approved a -> "ok: " + a.txId();
        case Declined d -> "declined: " + d.reason();
        case Pending p  -> "pending: " + p.ref();
    };
}
```

`instanceof` pattern matching removes casts:

```java
if (obj instanceof String s && !s.isBlank()) {
    return s.trim();
}
```

## Record patterns

Record patterns (final in Java 21) destructure records directly in `instanceof`
and `switch`, including nested records.

```java
record Point(int x, int y) { }
record Line(Point from, Point to) { }

String render(Object shape) {
    return switch (shape) {
        case Point(int x, int y)                 -> "point " + x + "," + y;
        case Line(Point(var x1, var y1),
                  Point(var x2, var y2))         -> "line";   // nested destructuring
        default                                  -> "unknown";
    };
}
```

## Text blocks

Multi-line string literals (final in Java 15) — ideal for SQL, JSON, and HTML
without escape-sequence noise.

```java
String sql = """
    SELECT id, email, status
    FROM users
    WHERE status = ?
    ORDER BY created_at DESC
    """;
```

## Sequenced collections

Java 21 added `SequencedCollection`, `SequencedSet`, and `SequencedMap`: a uniform
API for ordered collections with `getFirst()`, `getLast()`, `addFirst()`,
`addLast()`, and `reversed()` across `List`, `Deque`, and `LinkedHashSet`/`Map`.

```java
List<String> names = new ArrayList<>(List.of("a", "b", "c"));
names.getFirst();          // "a"  (no more get(0))
names.getLast();           // "c"
names.reversed();          // [c, b, a]
```

## Unnamed variables and patterns

The underscore `_` (final in Java 22) marks a variable or pattern binding you must
declare but never use — clearer intent, no "unused" warnings.

```java
// Unused exception variable
try {
    return Integer.parseInt(s);
} catch (NumberFormatException _) {
    return 0;
}

// Unused pattern component
if (point instanceof Point(int x, _)) {   // only need x
    use(x);
}
```

## Virtual threads

Virtual threads (final in Java 21) are lightweight threads managed by the JVM. You
can run millions of them, so the "one thread per request" model scales without
async complexity — ideal for I/O-bound backends.

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> callSlowService());   // blocking is cheap here
}
```

<Backend>
  Virtual threads make blocking JDBC/HTTP calls scalable again: a blocked
  virtual thread parks and frees its carrier OS thread. In Spring Boot 3.2+ you
  enable them with `spring.threads.virtual.enabled=true`.
</Backend>

## Scoped values & structured concurrency

`ScopedValue` (final in Java 25) is the modern, immutable replacement for
`ThreadLocal`: a value bound for the duration of a call, safely inherited by child
tasks and perfect for virtual threads.

```java
private static final ScopedValue<String> REQUEST_ID = ScopedValue.newInstance();

ScopedValue.where(REQUEST_ID, requestId).run(() -> handleRequest());
// deeper in the stack:
String id = REQUEST_ID.get();
```

**Structured concurrency** treats a group of concurrent subtasks as a single unit
of work — if one fails, the rest are cancelled, and the parent waits for all of
them. It remains a preview through JDK 27 (seventh preview, JEP 533).

```java
// Preview API — requires --enable-preview
try (var scope = StructuredTaskScope.open()) {
    var user  = scope.fork(() -> loadUser(id));
    var orders = scope.fork(() -> loadOrders(id));
    scope.join();                       // wait for both; propagate failure
    return new Dashboard(user.get(), orders.get());
}
```

## What's new in JDK 27

JDK 27 (September 15, 2026) is a non-LTS release with nine JEPs. Notably, it adds
no new language syntax — the four finalized features change JVM/security defaults
and need **zero code changes**.

| JEP | Feature                                             | Status    | Effect                                                                     |
| --- | --------------------------------------------------- | --------- | -------------------------------------------------------------------------- |
| 523 | G1 as the default GC everywhere                     | Final     | G1 is chosen even on 1-CPU / low-memory containers (was Serial)            |
| 534 | Compact object headers by default                   | Final     | Object header shrinks 96 → 64 bits; less heap for small-object-heavy apps  |
| 527 | Post-quantum hybrid key exchange for TLS 1.3        | Final     | `X25519MLKEM768` offered first — quantum-safe handshakes, transparently    |
| 536 | JFR in-process data redaction                       | Final     | Flight-recording data (passwords, secrets) shown as `[REDACTED]`           |
| 531 | Lazy constants                                      | Preview   | `Set.ofLazy()`; deferred, thread-safe initialization                       |
| 532 | Primitive types in patterns, `instanceof`, `switch` | Preview   | Pattern-match on `int`, `long`, etc.                                       |
| 533 | Structured concurrency                              | Preview   | `join()` now throws `ExecutionException`; adds an exception type parameter |
| 538 | PEM encodings of cryptographic objects              | Preview   | `PEM` becomes a class; read/write keys and certs in PEM                    |
| 537 | Vector API                                          | Incubator | SIMD computations; waiting on Project Valhalla                             |

<Backend>
  The two defaults you'll feel in production without touching code: **compact
  object headers** (JEP 534) cut heap for services with many small objects — one
  JEP benchmark saw ~22% less heap — and **G1 everywhere** (JEP 523) changes GC
  behavior in small single-CPU containers. If a tiny service ran better on
  Serial, opt back in with `-XX:+UseSerialGC`.
</Backend>
