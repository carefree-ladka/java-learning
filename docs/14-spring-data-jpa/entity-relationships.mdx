## The owning side

<Important>
In JPA the **owning side** holds the foreign key and controls the association in the
database. The inverse side uses `mappedBy` to point at the owning field and is
read-only for the FK. Set the owning side or your changes won't persist.
</Important>

## Many-to-One / One-to-Many

The most common pair. `@ManyToOne` is the owning side (holds the FK column).

```java
@Entity
public class Order {
    @Id @GeneratedValue Long id;

    @ManyToOne(fetch = FetchType.LAZY)     // owning side: orders.customer_id
    @JoinColumn(name = "customer_id")
    private Customer customer;
}

@Entity
public class Customer {
    @Id @GeneratedValue Long id;

    @OneToMany(mappedBy = "customer")      // inverse side, read-only for FK
    private List<Order> orders = new ArrayList<>();
}
```

<Warning>
Default fetch for `@ManyToOne`/`@OneToOne` is **EAGER**, for `@OneToMany`/`@ManyToMany`
is **LAZY**. Make `@ManyToOne` explicitly `LAZY` — eager associations trigger extra
queries and fuel the N+1 problem.
</Warning>

## One-to-One

```java
@Entity
public class User {
    @Id @GeneratedValue Long id;

    @OneToOne(fetch = FetchType.LAZY, cascade = CascadeType.ALL)
    @JoinColumn(name = "profile_id")
    private Profile profile;
}
```

## Many-to-Many

Backed by a join table. Prefer modeling it as two `@ManyToOne`s on an explicit join
entity when the relationship carries its own data (e.g. quantity, added-at).

```java
@Entity
public class Student {
    @ManyToMany
    @JoinTable(
        name = "student_course",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id"))
    private Set<Course> courses = new HashSet<>();
}
```

## Cascade & orphan removal

- **Cascade** propagates operations from parent to children (`PERSIST`, `MERGE`,
  `REMOVE`, `ALL`).
- **orphanRemoval = true** deletes a child when it's removed from the parent's
  collection.

```java
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<LineItem> items = new ArrayList<>();

// removing from the list deletes the row on flush
order.getItems().remove(item);
```

<Warning>
Don't put `CascadeType.REMOVE`/`ALL` on `@ManyToOne` — deleting one order should not
delete the shared customer. Cascade flows parent → owned children, not child → shared
parent.
</Warning>

## Common mistakes

<Warning>
- Forgetting `mappedBy`, creating a duplicate join table or an extra FK column.
- Leaving `@ManyToOne` EAGER, causing N+1 and huge object graphs.
- Not maintaining both sides of a bidirectional relationship in memory (add helper
  methods like `order.addItem(item)` that set both ends).
- `Set` vs `List` for collections — use `Set` for many-to-many to avoid duplicates.
</Warning>

## Interview questions

**Q: Owning vs inverse side?**
The owning side maps the FK and controls persistence; the inverse side declares
`mappedBy` and is read-only for the association.

**Q: Default fetch types?**
`@ManyToOne`/`@OneToOne` = EAGER, `@OneToMany`/`@ManyToMany` = LAZY. Make to-one
associations LAZY explicitly.

**Q: What does orphanRemoval do?**
Deletes a child entity when it's disassociated from its parent collection.
